# RC gate execution and evidence integrity — Pass 24

Current version remains 0.6.5-rc.1. This guide is an operating procedure for an approved dedicated runner; it is not permission to run workloads, change quotas, enable repository approval variables, or dispatch the runtime workflow. Do not use the developer or production host for integration, ABBA, rollback, PSI-crossing, or soak evidence.

## Changes in this pass

- Router singleton locking is nonblocking and owner-only; failure to acquire it disables that instance before state reads or controller side effects. Do not delete a lock file to “fix” a conflict: identify the holder and wait for its process to exit naturally.
- Unknown /proc membership is not treated as process exit. State is retained and recovery baselines are reset until a valid membership sample returns. Known-heavy routing now depends on parsed argv/tool subcommands rather than accidental substrings inside ordinary program arguments.
- On a graceful SIGTERM/SIGINT stop, verified routed PIDs are moved to the protected recovery child, which inherits the protected parent's CPU quota. The router checks the stored process starttime before moving and verifies destination membership before dropping its route record. PID reuse is pruned without moving the new process; unknown membership, failed moves, or uncertain readback preserve state for the next start. SIGKILL cannot promise immediate cleanup, so the route journal is the restart recovery source.
- Shutdown obtains the parent/heavy/recovery `ControlGroup` values in one bounded systemd request and applies an 8.5-second total cleanup deadline. Routed-PID recovery is limited to at most five seconds within that budget; aggregate-scope cleanup receives only the time left and defers its restore if effective readback cannot fit, preserving the state journal rather than blocking systemd stop.
- Aggregate-scope reconciliation batches systemd property reads and limits restoration to one scope per sampling cycle. It verifies exact CPUWeight readback and cgroup identity and suppresses control after detecting an external weight edit. If systemd telemetry is unavailable, restoration is deferred and state is retained; investigate the service manager rather than repeatedly restarting the daemon.
- benchmarks/evidence_integrity.py creates and verifies a SHA-256 manifest for each newly generated routing benchmark run. All six files must be regular files: result TSV, raw samples TSV, environment manifest, router log, interval telemetry TSV, and throughput counters TSV. The evidence manifest is create-only; never reuse or overwrite a run path. A valid hash proves bytes match the manifest, not experiment validity or host independence. Preserve the manifest digest in the independent review record to detect coordinated rewriting of both data and manifest.
- The performance evaluator returns INCOMPLETE rather than PASS for missing/tampered run manifests, duplicate environment keys, or inconsistent inputs. Aggregate analysis binds acceptance files to exact result/raw/environment paths and rejects duplicate keys and copied stale reports. PSI rules and all pre-registered samples remain unchanged.
- Runtime/controller integration was moved out of the generic push/PR CI workflow into a distinct workflow_dispatch-only workflow. The dedicated runtime workflow remains gated on main, both repository approval variables, and the explicit runner label. It was not dispatched and no approvals were enabled.
- Follow-up Pass 25 clarification: `run_status=COMPLETE` means collection integrity only. The soak collector separately records `soak_gate_status=OPEN_DURATION_BELOW_24H` for runs shorter than 86,400 monotonic seconds; a longer clean trace remains `REQUIRES_WORKLOAD_PHASE_LOGS_AND_HUMAN_REVIEW`. See [`rc-gate-execution-pass25.md`](rc-gate-execution-pass25.md).

## Before using the approved runner

1. A repository owner must approve the dedicated runner and its isolation from production workloads. An operator must independently verify Ubuntu release, kernel, systemd user manager, cgroup v2 CPU delegation, writable temporary test-slice delegation, and the required cpu.stat fields: usage_usec, nr_periods, nr_throttled, and throttled_usec. Root-cgroup counters do not prove delegation inside the actual test slice.
2. Confirm the exact reviewed main commit, version 0.6.5-rc.1, a clean tracked worktree, enough disk space, and a unique new output directory. Preserve the 254 historical untracked artifact entries; do not bulk-stage benchmarks/results.
3. Use the read-only preflight only as discovery evidence, for example benchmarks/rc-gate-preflight.sh benchmarks/results/<new-preflight-dir>. It writes environment/provenance and a local SHA-256 manifest; it does not test actuation or close any gate. Record its command, timestamps, exit status, source revision, host inventory ID, stdout/stderr, and verifier output.
4. Runtime CI is intentionally in .github/workflows/approved-controller-runtime.yml, separate from push/PR CI. Only an authorized owner may decide whether to enable the two repository variables and manually dispatch from main to the specifically labelled lwg-approved-controller-test runner. This pass did not enable either variable and did not dispatch the workflow. Never copy runtime commands into generic hosted CI.

## ABBA and throughput procedure on an approved host

Only after the operator and repository owner have verified runner authorization, create a preregistration in a unique new directory on the approved host with benchmarks/preregister_abba.py create and its explicit independent-host, operator, workload, and approved-window confirmations. Review protocol.json, SHA256SUMS.txt, source commit, host inventory assertion, cgroup v2 capability, fixed thresholds, block order and command contract; then run benchmarks/preregister_abba.py verify. Do not create the seal after looking at outcomes.

Execute A (weight 20), B (80), B2 (80), A2 (20) in that exact order, binding every block to the same sealed protocol directory and using a fresh result filename. Use the preregistered workload kind, two workers, five repetitions and 30-second modes. The isolated harness creates temporary workload scopes and a shared 100% parent CPU ceiling; it must not alter production units or production policy. Preserve all raw samples and all failed/incomplete blocks. After each run verify the evidence manifest before reviewing the report. After all four blocks, run performance review for each output and aggregate analysis to a new output path; preserve their exact commands and exit codes.

The fixed PSI confounder rules are not tunable per run: more than 20% of steady-window host some avg10 samples above 5% in any mode/pair, or a baseline/router median imbalance greater than 5 percentage points, yields CONFOUNDED_INCONCLUSIVE; all samples are retained. Missing/invalid PSI is not evidence of quiet conditions. The throughput lower bound remains 0.90, and the latency/probe-work ratio bound remains 1.10.

## Evidence integrity and diagnosis

- Never modify a run artifact after the create-only manifest is written. If any file changes, keep the failed output as-is, mark it invalid/incomplete, and collect a new run into a new path.
- Existing or dangling symlink output paths count as occupied. Do not remove them automatically; choose a different unique result path and review any symlink source independently.
- Review evidence_integrity.py through the evaluator and verify SHA256SUMS.txt in the outer validation bundle separately. Keep the digest of the run evidence manifest in the signed/independent review record; a manifest cannot defend itself against coordinated rewriting of the manifest and its files.
- The aggregate analyzer verifies that an evaluator report references the exact input result TSV, its raw sample TSV, and its environment manifest. Do not rename a run and assume an old acceptance report follows the rename; rerun review with a new output path.
- Missing cpu.stat, PSI, scheduler delay, quota property, systemd unit identity, or readback is unknown/incomplete. Never replace absent observations with zero. A failed write or mismatched readback must not be reported as success.
- If route state is unexpectedly retained, investigate read permissions and /proc/<pid>/cgroup; unknown membership is intentionally preserved to avoid orphaning live processes. If the singleton lock cannot be acquired, identify the competing process rather than unlinking its lock file. If a scope's weight changes externally, the router suppresses further control over that scope rather than reasserting its setting.
- Dynamic quota stays opt-in. Production PSI threshold remains 0.40. Do not change the 0.90 throughput gate, PSI confounder protocol, block order, sample exclusions, resource limits, or preregistration requirements to make a result pass.

## Final review

For every validation command, record literal command, start/end timestamp, numeric exit status, output/log path, host and source provenance. Generate the outer SHA256SUMS.txt only after all bundle content is final and run sha256sum -c SHA256SUMS.txt. A checksum PASS proves bundle integrity only. Reviewer sign-off must independently check every gate row above. Routine CI, unit tests, a sealed protocol, passive observation without a crossing, or a complete collector run alone never closes runtime acceptance.
